# Marbble roadmap

**Stage: alpha.** Next: beta.

Marbble aims to be what Pro Tools is among DAWs: not every feature Logic Pro has, but a complete,
solid core for recording, editing, mixing and delivering, that runs well and never loses work, with
plug-ins doing the rest. This page says what beta needs, how far along that is, and what's being
worked on. The [feature list](docs/FEATURES.md) has every Logic Pro feature by area and how far
Marbble has it, and every open item is an [issue][issues].

## What beta needs

- **The core features.** Every feature marked `beta = true` in [`features/`](features/README.md):
  the essentials of Logic Pro's interface, projects, transport, recording, tracks, arranging,
  editors, Mixer, plug-in hosting, MIDI devices and bouncing. Logic's extras (the Brush tool, the
  Toolbar, the giant display, several open projects and the like) wait until after beta. The
  issues for the ones still to build are in the [Beta: core features][beta milestone] milestone.
- **Stages 1 and 2 below.** Prereleases that install cleanly, and plug-ins that work the same on
  Windows and macOS as on Linux.
- **No known bug that crashes or loses work**, and the checks labelled [`needs a look`][needs a look]
  and [`needs listening`][needs listening] done.

What's left for beta, by area (◐ partial, ○ missing):

**Interface and settings**

- ◐ Control bar: view buttons, transport, LCD, Cycle, Count-in, Metronome, master volume, CPU ([#322](https://github.com/JackMechem/marbble/issues/322)): Fixed layout, but for the CPU meter, which Settings › Appearance puts here or in the status line; no Customize Control Bar.
- ◐ LCD display modes ([#323](https://github.com/JackMechem/marbble/issues/323)): Beats and Time only; no Custom mode or large LCD.
- ◐ Right inspector strip follows the left strip's output or aux ([#324](https://github.com/JackMechem/marbble/issues/324)): Always shows Stereo Out.
- ◐ Project notes ([#325](https://github.com/JackMechem/marbble/issues/325)): Free-form notes in Project Settings; no Note Pad pane.
- ○ Track notes ([#325](https://github.com/JackMechem/marbble/issues/325))
- ◐ Zoom to fit selection or all content (Z) ([#326](https://github.com/JackMechem/marbble/issues/326)): In the Piano Roll and Audio Track Editor; not in the Tracks area.
- ◐ Open, close and focus windows ([#327](https://github.com/JackMechem/marbble/issues/327)): The Window menu brings any open window to the front or minimises it, and the Mixer, Editors, Event List, Step Sequencer and effect panels open in windows of their own; no second main window.
- ◐ Customisable keys ([#328](https://github.com/JackMechem/marbble/issues/328)): Window keys only; menu shortcuts are fixed.
- ○ Save, import and choose key command sets ([#329](https://github.com/JackMechem/marbble/issues/329))
- ◐ Project Settings ([#330](https://github.com/JackMechem/marbble/issues/330)): Tempo, signature, key, sample rate, bit depth, metronome and notes; most of Logic's project panes are missing.
- ○ Reset all settings ([#331](https://github.com/JackMechem/marbble/issues/331))
- ○ Notifications: reset "don't show again" warnings ([#332](https://github.com/JackMechem/marbble/issues/332))

**Projects**

- ◐ Project Chooser ([#333](https://github.com/JackMechem/marbble/issues/333)): New, Recent and Open, with four built-in templates and the user's own (My Templates); no demo projects or tutorials.
- ◐ Save a copy including all assets ([#334](https://github.com/JackMechem/marbble/issues/334)): Save As into a new folder copies every file the project uses into it; no Save a Copy As that leaves the open project as it is.
- ○ Delete a project from the chooser ([#335](https://github.com/JackMechem/marbble/issues/335))
- ○ Project start and end points ([#336](https://github.com/JackMechem/marbble/issues/336))
- ○ Close Project without quitting ([#337](https://github.com/JackMechem/marbble/issues/337))

- ○ Transport shortcut menus on Play and Stop ([#315](https://github.com/JackMechem/marbble/issues/315))

**Mixing and automation**

- ◐ Channel strip types ([#362](https://github.com/JackMechem/marbble/issues/362)): Audio, instrument, aux, summing stack, VCA and Stereo Out; no MIDI, output or master strips.
- ◐ Reorder strips ([#363](https://github.com/JackMechem/marbble/issues/363)): Follows the track order.
- ◐ Search for plug-ins ([#364](https://github.com/JackMechem/marbble/issues/364)): The Library has search; slot menus are grouped by vendor and category, without search.
- ◐ Plug-in windows ([#99](https://github.com/JackMechem/marbble/issues/99)): Built-in effect panels everywhere; a VST3's own editor on Linux/X11 and macOS so far.
- ○ Select several strips, or strips by type ([#365](https://github.com/JackMechem/marbble/issues/365))

**Plug-ins**

- ◐ Plug-in Manager ([#366](https://github.com/JackMechem/marbble/issues/366)): Hide plug-ins, add VST3 folders, rescan, view the scan report; no categories or custom names.

**MIDI and hardware**

- ◐ Receive MIDI from other apps ([#355](https://github.com/JackMechem/marbble/issues/355)): Through system MIDI ports; Marbble doesn't create a virtual port of its own.
- ○ Local Off: stop a keyboard's own sound generation ([#356](https://github.com/JackMechem/marbble/issues/356))

**Import, export and media**

- ◐ All Files Browser ([#357](https://github.com/JackMechem/marbble/issues/357)): Browses folders; no search conditions or bookmarks.
- ○ Open a MIDI file as a new project ([#358](https://github.com/JackMechem/marbble/issues/358))

- ◐ Dither ([#359](https://github.com/JackMechem/marbble/issues/359)): TPDF only; no POW-r.
- ◐ Bounce all tracks in place ([#360](https://github.com/JackMechem/marbble/issues/360)): Works on the selected tracks; no dedicated command.

## Current focus

Work goes in rounds of a few issues at a time. What's being built right now is in the issues
labelled [`in progress`][in progress]. The rounds planned towards beta, in order:

1. **Stability and performance.** This comes first now, ahead of new features: the dropouts and
   System Overloads under load ([#35], [#16]), several processing threads on macOS and Windows
   ([#59]), the stuck-plug-in handling with a real VST3 ([#114]), the checks that fail now and then
   ([`flaky test`][flaky test]), and any bug that crashes Marbble or loses work.
   macOS is now level with Linux (0.1.0-alpha.15: real-time processing threads in the audio
   device's workgroup, Automatic above one thread, audio that follows a changed or unplugged
   device). The round under way ([#416]) takes on the flaky checks, follow-ups to the automatic
   device restarts, and longer soak runs looking for bugs that break undo, saving or renders.
2. **Plug-in hosting.** Keys from VST3 editors on Linux ([#88]), editors following a display scale
   change ([#94]), the Plug-in Manager, plug-in search and plug-in windows in the Mixer, Compare
   for VST3 plug-ins ([#292]); then CLAP hosting ([#105]).
3. **Transport and navigation.** Pause, fast forward and rewind, Play from Selection, Go to
   Position, locators typed into the LCD, the cycle and transient key commands.
4. **Projects, tracks and delivery.** Save a copy with its assets, Close Project, project start and
   end, opening a MIDI file as a project, real-time bounce and dither, searching, renaming and
   sorting tracks.
5. **Editing and the Mixer.** Scale-constrained note input, time handles, note labels and drum
   names in the Piano Roll, selecting and reordering Mixer strips, the track header's width and
   controls, key command sets.

## Stages

The stages are [milestones][milestones] on GitHub, in the order they matter for a usable release.
Each milestone lists its open and closed issues.

- **[Stage 1: Release hygiene][stage 1]:** prereleases that install cleanly and that people can
  trust with their projects.
- **[Stage 2: Plug-ins on every platform][stage 2]:** a VST3 user on Windows or macOS gets the same
  workflow as on Linux.
- **[Stage 3: Audio editing][stage 3]:** clean, fast audio editing and comping without workarounds.
- **[Stage 4: MIDI and control][stage 4]:** precise MIDI editing and hands-on control from hardware.
- **[Stage 5: Mixing and delivery][stage 5]:** finish a mix and deliver it without leaving Marbble.
- **[Stage 6: Advanced production][stage 6]:** the larger Logic features that set a full DAW apart.
- **[Stage 7: Formats and reach][stage 7]:** more plug-ins, more people.

## Open work

Besides each stage's milestone, a few labels gather the open work that doesn't belong to one stage:

- [`bug`][bug]: known bugs and unexplained failures.
- [`needs a look`][needs a look]: built and tested, but not yet checked by eye in the running app.
- [`needs listening`][needs listening]: passes its checks, but nobody has listened to it or tried it
  on a real interface yet.
- [`platform: windows`][platform: windows] and [`platform: macos`][platform: macos]: what still
  needs a real Windows or Mac.
- [`flaky test`][flaky test]: checks that fail now and then.
- `area: …` labels group the rest by part of Marbble ([instruments][area: instruments],
  [sampler][area: sampler], [multi-core][area: multi-core], [ui][area: ui] and so on).
